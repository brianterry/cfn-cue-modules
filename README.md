# cfn-cue-modules

Typed CUE modules for all AWS CloudFormation resource types with compliance constraints. Published to the [CUE Central Registry](https://registry.cue.works).

## Install

```bash
cue mod get github.com/brianterry/cfn-cue-modules@v0
```

That's it. CUE will download the module and make it available for import.

## Usage

```cue
package infra

import (
    "github.com/brianterry/cfn-cue-modules/cfn"
    "github.com/brianterry/cfn-cue-modules/fn"
    "github.com/brianterry/cfn-cue-modules/resources/s3/bucket"
    "github.com/brianterry/cfn-cue-modules/resources/s3/bucket/compliance"
)

stack: cfn.#Stack & {
    AWSTemplateFormatVersion: "2010-09-09"
    Description: "My secure S3 bucket"

    Resources: {
        // Type-checked and compliance-enforced
        MyBucket: bucket.#Resource & compliance.#NIST800_53Rev5 & {
            Properties: {
                BucketName: "my-bucket"
                BucketEncryption: ServerSideEncryptionConfiguration: [{
                    ServerSideEncryptionByDefault: SSEAlgorithm: "aws:kms"
                }]
                PublicAccessBlockConfiguration: {
                    BlockPublicAcls:       true
                    BlockPublicPolicy:     true
                    IgnorePublicAcls:      true
                    RestrictPublicBuckets: true
                }
            }
        }
    }

    Outputs: BucketArn: {
        Value: fn.#GetAtt & {"Fn::GetAtt": ["MyBucket", "Arn"]}
    }
}
```

Then validate and export:

```bash
cue vet ./...                           # Type check + compliance
cue export . -e stack --out yaml        # Produce CloudFormation YAML
```

## What's Included

| Package | What |
|---------|------|
| `cfn` | Base types: `#Stack`, `#ResourceBase`, `#Parameter`, `#Output`, `#Tag` |
| `fn` | Intrinsic functions: `#Ref`, `#GetAtt`, `#Sub`, `#Join`, `#If`, etc. |
| `resources/<service>/<resource>` | Typed resource modules (1,651 total) |
| `resources/<service>/<resource>/compliance` | Compliance constraints per framework |

## Available Resources (1,651)

Every AWS CloudFormation resource type is available. Examples:

```cue
import "github.com/brianterry/cfn-cue-modules/resources/ec2/instance"
import "github.com/brianterry/cfn-cue-modules/resources/lambda/function"
import "github.com/brianterry/cfn-cue-modules/resources/dynamodb/table"
import "github.com/brianterry/cfn-cue-modules/resources/iam/role"
import "github.com/brianterry/cfn-cue-modules/resources/rds/dbinstance"
import "github.com/brianterry/cfn-cue-modules/resources/ecs/service"
import "github.com/brianterry/cfn-cue-modules/resources/cloudfront/distribution"
```

Each resource module provides:
- `#Resource` — the typed resource definition (unify with your resource)
- `#Properties` — all properties with types, enums, patterns, and constraints
- `#Attributes` — read-only return values available via `Fn::GetAtt`

## Compliance Frameworks (50)

Import compliance constraints to enforce security policy at authoring time:

```cue
import "github.com/brianterry/cfn-cue-modules/resources/s3/bucket/compliance"

// Unify to enforce — violations become compile errors
MyBucket: bucket.#Resource & compliance.#NIST800_53Rev5 & { ... }
```

Available frameworks include:
- NIST 800-53 Rev 4 & Rev 5
- CIS AWS Benchmark Level 1 & 2
- PCI-DSS 3.2.1
- HIPAA Security Rule
- FedRAMP Low, Moderate, High
- SOC 2
- CMMC Level 1–5
- CIS Critical Security Controls v8
- And 40+ more

## How It Works

1. **Type safety** — Properties are typed with enums, patterns, and numeric constraints from the CF schema. Invalid values are caught immediately.
2. **Compliance enforcement** — Compliance definitions use CUE's unification. When you unify a resource with a compliance constraint, any missing or invalid property becomes a CUE error.
3. **Clean output** — `cue export` produces standard CloudFormation YAML/JSON ready for `aws cloudformation deploy`.
